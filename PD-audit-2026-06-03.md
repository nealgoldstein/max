For the modal flow, only PD.91 runs. PD.75 / role-write loop does not. Several of my fixes lived in the wrong path.

## State of the picker after this cleanup

What works:
- Classifier fires correctly on your path. `_userListedNames` correctly splits stays from sees.
- Parser respects `stays:` / `sees:` sub-headers.
- Modal's `parseSection` tags entries with `_userIntent`.
- Stays-win dedup when a place is in both fields.
- "Recommended overnight stays" section shows correctly via PD.91.

What doesn't:
- Discovery-map render rules from the original spec (`parentRelation: "within" | "from"`) are not implemented.
- Change-role atomic mutation from the spec is not implemented.
- The dedup invariant (PD.207) and the publish-time sight attachment have not been exercised because no trip has been Choreographed past the picker yet.

## What I think I learned

- I should have traced from button-click to function-call before any code edit. I traced function names but skipped the "is this button on this user's path" step, which is why PD.212 / PD.213 / PD.214 landed in the wrong place.
- The codebase has architectural patterns (PD.75 vs PD.91, two render times) that I learned about by patching the wrong one. A pre-flight architecture read of the picker render lifecycle would have caught it.
- Each PD I shipped added cognitive load. Even the live-and-verified ones overlap (PD.215 and PD.219 both set `_userIntent` for different paths). Once we agree on a direction, some consolidation would be healthy.
