# P4.5 — Persist the decision log; retire the record `_keep` / `_decided` flags

The last slice of the perfect-model effort. P4.1–P4.4 separated FACTS from
DECISIONS from the derived VIEW, made keep a pure projection (P4.3), and
collapsed the candidate arrays + deleted `mirror()` (P4.4). What remains: make
the **decision log itself** the persisted, authoritative record of the user's
choices, and retire the per-record `_keep` / `_decided` flags it currently
shadows.

This is the **highest-stakes** path in the app — it decides whether a saved
trip's check-state survives reload. Do it cold, one slice per sitting, behind
the full browser gate. Unlike the earlier slices, the dangerous part here is
LOAD + PERSIST, so the gate's **decision round-trip** (publish → reload →
decisions survive) is the load-bearing test.

---

## Where things stand (after P4.4)

- **Decision model** (`decision-model.js`): `Decision { kept, rejected, role, hub, leg }`,
  the `Decisions` log (keyed by normalized place identity), and pure projections
  `keepOf` / `roleOf` / `sectionOf` / `project`. 17 property tests.
- **Keep is projected** (P4.3): `_reconcileUserListedKeeps` sets each record's
  `_keep` via `MaxDecisions.keepOf` reading `_tb._decisions`.
- **The log is WRITTEN** by exactly two doors: `MaxRoleWriter.set`
  (`geography-model.js`) and `_recordWaysideLegDecision` (P4.4c).
- **Live shadow check**: `_p4ShadowCheck()` (`index.html`) asserts
  `keepOf(facts, decision) === record._keep` for every decided place.

### The two facts that make this a phase, not a slice

1. **The log is SPARSE and TRANSIENT.** It lives on `_tb._decisions` (the picker
   buffer), gets entries only when the user acts, and is **not serialized** —
   `serializeTrip()` (`index.html` ~3486) persists only `trip`. The durable
   record of "what the user kept" today is the per-record `_keep` / `_decided`
   flags inside `trip.placeActivities[].requiredPlaces[]` (+ `trip.candidates`
   `status`). So the log can't yet BE the source — it doesn't survive reload and
   doesn't cover untouched places.
2. **`_keep` has a wide readership** — ~150 sites (93 in `index.html`). Retiring
   it means every keep READER must go through the projection, not the raw flag.

## The slices (each = its own commit + full gate; shadow-prove before cutover)

Rising risk. After each: `bash tests/run.sh`, `./dev.sh check`, commit. Use the
shadow/parallel trick (run old + new, assert agreement via `_p4ShadowCheck`,
THEN delete the old) — exactly like P4.2/P4.3/P4.4.

### P4.5a — make the log COMPREHENSIVE (shadow; non-load-bearing)
On load/build, seed `_tb._decisions` with a decision for **every** place derived
from the current durable flags + origin, so `keepOf(facts, log)` reproduces the
existing `_keep` for all places (not just user-touched ones). Keep the record
flags load-bearing. Gate: `_p4ShadowCheck()` reports zero mismatches; decision
round-trip still green.

### P4.5b — PERSIST + restore the log (shadow)
Add `MaxDecisions.toJSON` / `fromJSON`. At save, serialize `_tb._decisions` into
the trip envelope (e.g. `trip.brief._decisionLog`). At load, restore it into
`_tb._decisions`; fall back to the P4.5a record-seed only when the envelope has
no log (legacy trips). Still non-load-bearing (records still drive keep). Gate:
a restored-from-storage log equals the record-seeded log (shadow assert);
decision round-trip green.

### P4.5c — cut the keep DERIVATION to the log (the big one)
Make the projection read the persisted log as the **sole** keep source, and
route the ~150 `_keep` readers through one accessor (`keepOfRecord(p)` /
`MaxDecisions.keepOf`) instead of reading the raw flag. Do it in batches by
file, gate between batches. The record `_keep` becomes a derived cache written
once per render from the projection (not yet deleted). Gate: decision
round-trip + build-harness green.

### P4.5d — retire the record flags
Stop writing `_keep` / `_decided` on records; delete the seed-from-records
(keep only a legacy-trip migration that builds the log from old flags on first
load). The log is the one write surface and the one persisted truth. Gate: full
browser gate + a legacy-trip load test.

## Pre-flight (before any cutover)
- Gate green on current code (done — P4.4 left 58 pw / 959 node green).
- Confirm `_p4ShadowCheck()` is reachable and reports clean on a built trip
  (it's the safety net for P4.5a/b).
- Tag a rollback point: `git tag p4.5-start`.

## Discipline
- One slice per sitting. Commit after each. **Never** chain the persist/load
  edits in a single silent run.
- If the decision round-trip goes red and isn't trivially fixable, **revert the
  slice** (`git reset --hard` to the last slice commit) rather than patch forward.
- Don't repeatedly reopen the live trip while testing; never let a half-built
  state save over a good trip.

## Done when
The persisted decision log is the single authoritative record of the user's
choices; `_keep` / `_decided` are gone (or a thin derived cache); a trip — new
AND legacy — survives publish → reload with every keep/role/hub/leg decision
intact; the full gate is green.
