# P4.4 — Collapse the two candidate arrays, delete `mirror()`

A focused-session brief. The goal of P4.4 is to make `_tb.candidates` (the rich
working buffer) and `trip.candidates` (the lean persisted snapshot) into **one
array**, so `mirror()` and the dual-shape bookkeeping disappear. This is the
highest-risk slice in the whole effort because it touches the **publish → reopen
→ reload** path — the only code that can corrupt a saved trip. Do it cold,
behind a real test gate, one slice per sitting.

---

## Where things stand (already done, committed)

The discovery keep/role/section subsystem is referee-free and the keep engine is
already a pure projection:

- **Decision model** (`decision-model.js`): `Decision`, `Decisions` (the log),
  and pure projections `keepOf(facts, decision)`, `roleOf`, `sectionOf`,
  `project`. 12 property tests (`tests/decision-model-tests.js`).
- **Keep is projected** (P4.3): `_reconcileUserListedKeeps` (in `index.html`)
  now sets `_keep` via `MaxDecisions.keepOf` reading `_tb._decisions`. The log is
  seeded from persisted record flags on load, then authoritative.
- **One snapshot projection** (`MaxCandidates.snapshotOf`/`snapshotFrom` in
  `geography-model.js`): the single birth point of `trip.candidates`, used by
  both `publishTrip` (`engine-picker.js`) and `applyCandidateChanges`
  (`edit-constraints.js`). 8 property tests (`tests/candidates-snapshot-tests.js`).
- **One mirror primitive** (`_mirrorCandToTrip` / `MaxRoleWriter.mirror` in
  `geography-model.js`): syncs decision fields from the working candidate to its
  snapshot twin. **This is what P4.4 deletes.**
- Live diagnostic: `globalThis._p4ShadowCheck()` (in `index.html`) audits that
  the decision log agrees with the live record flags.

Test gate today: `bash tests/run.sh` → **954 green** (Node). Dev server with
no-cache: `./dev.sh serve`. Full gate (Node + Playwright): `./dev.sh check`.

---

## Why the arrays are still two (the core fact)

They are intentionally **different shapes**:

- `trip.candidates` — **lean persisted snapshot**. Born only via
  `MaxCandidates.snapshotFrom`. Read by the trip view / map pins after reload.
- `_tb.candidates` — **rich working buffer**. Hydrated from `trip.candidates`
  with a `.map()` that ENRICHES it (see `edit-constraints.js`
  `reopenCandidateExplorer` / `reopenPickerForEdit`, ~line 1816) with fields the
  snapshot does not carry: `singleSight`, `waysideLeg`, `tripRole`.

Lifecycle subtlety (confirmed): on the **trip view**, `index.html` (~line 18434)
sets `_tb.candidates = trip.candidates` **by reference** — so there they are the
same array and `mirror()` is a no-op. In the **picker**, hydration is a `.map()`
copy, so there `mirror()` is load-bearing. The collapse = make the picker stop
needing a richer copy, so it can share the reference too.

`mirror()` call sites to remove at the end: `MaxRoleWriter.set` (internal),
`picker-hero-sidebar.js` (must-do drop ~1037, status toggle ~1245).

## The three enrichment fields (the homework)

| field | nature | plan |
|---|---|---|
| `tripRole` | **vestigial** — "NC.1 transitional, retired" in comments; migrated onto `role` by `normalizeCandidateRole` (`engine-picker.js` ~190); `delete`d in places. | remove from hydration; keep the legacy migration for old saved trips. |
| `singleSight` | **derivable fact** (used ~384×) — tracks `overnightCapable`, which the snapshot already persists. | add one `isSingleSight(c)` accessor, route reads, stop storing. |
| `waysideLeg` | **a decision attribute** — `{fromPlace, toPlace}`, records where the user placed a wayside (see `discovery-curation.js` ~213–233, `picker-ui.js` ~1364+, read in `engine-picker.js` ~3599). NOT a place fact. | move it INTO the decision log (next to `role`/`hub`). |

Once those three are handled, the working and persisted shapes converge and the
array can be one.

## Pre-flight (before ANY refactor)

1. Clean git state; tag a rollback point: `git tag p4.4-start`.
2. **Build the browser test gate first** (`tests/playwright/`). The publish/
   reopen/reload path is NOT Node-testable, so these are the real safety net.
   Pin today's behavior so a regression is caught immediately:
   - **wayside round-trip**: place a wayside on a leg → publish → reopen picker →
     leg assignment survived.
   - **singleSight render**: a single-sight place renders identically.
   - **decision round-trip**: check / uncheck / commit-a-Max-base / set a
     day-trip → publish → reload → all decisions survived.
   - run `./dev.sh check` and confirm these pass on **current** code first.

## The four slices (each = its own commit + full gate)

Do them in this order (rising risk). After each: `bash tests/run.sh` (954+),
`./dev.sh check` (browser gate), live spot-check, then commit. Use the
shadow/parallel trick — run old + new together, assert agreement, THEN delete the
old — exactly like P4.2/P4.3.

1. **P4.4a — retire `tripRole`.** Remove from the hydration map
   (`edit-constraints.js`) and anywhere it's written defensively. Keep
   `normalizeCandidateRole`'s `tripRole → role` migration so legacy trips load.
   Gate: browser decision round-trip still green.

2. **P4.4b — derive `singleSight`.** Add `isSingleSight(candidate)` (one place,
   reading `overnightCapable` / the classification). Route reads through it; stop
   writing the stored field in hydration + snapshot-adjacent maps. Gate:
   singleSight-render browser test.

3. **P4.4c — move `waysideLeg` into the decision.** Add `leg` to
   `decision-model.js` `Decision` (+ tests). Write it through `MaxRoleWriter` when
   a wayside is assigned; read it from the decision instead of the candidate.
   Shadow-prove equivalence first. Gate: wayside round-trip browser test.

4. **P4.4d — collapse + delete `mirror()`.** Shapes now match. Make the picker
   hydration share the reference (`_tb.candidates = trip.candidates`) instead of
   `.map()`-copying; regenerate the lean snapshot at save via
   `MaxCandidates.snapshotFrom`; delete `_mirrorCandToTrip`,
   `MaxRoleWriter.mirror`, and its call sites. This is the payoff and the only
   truly dangerous step — it goes LAST, ALONE, behind the full browser gate.

---

## Discipline

- One slice per sitting. Commit after each. **Never** chain the publish-path
  edits in a single silent run.
- If a browser-gate test goes red and isn't trivially fixable, revert the slice
  (`git reset --hard` to the last slice commit) rather than patch forward.
- Don't repeatedly reopen the live trip while testing — read trips read-only
  where possible; don't let a half-built state save over a good trip.
- Stale modules are the recurring trap: confirm fresh code with
  `typeof window._pmSurgicalKeepUpdate === "function"` (and after wiring, the new
  symbols) before trusting any live result. Restart `./dev.sh serve` after edits.

## Done when

`_tb.candidates` and `trip.candidates` are one array, `mirror()` and the three
enrichment fields are gone, the browser gate + 954 Node tests are green, and a
trip survives publish → reload with every decision intact. Then P4.5 (persist the
decision log directly, retire the record `_keep`/`_decided` flags) is the final
slice.
